How it works

You handle the human front. Foundation pushes the first-slice tenant build. One tenant or many. Consulting stays optional.

1. Create the new Microsoft tenant

A new Microsoft 365 tenant — yours, or a client’s. Foundation does not open the tenant for you. That step stays human.

2. Create admin accounts

Named admins and the break-glass pair exist before anything is pushed. You own those identities. The package will not invent them.

3. Order the SKUs / licenses

Business Premium or E3, in the quantities the tenant needs. Licences have to be in the tenant before Foundation can assign them from groups.

4. Push Foundation — unattended

The package applies the first-slice build. Dry-run first, then the write. Sign-in policy goes live in report-only so you can see the effect before anyone is blocked. You keep the configuration record and the runbooks.

Optional consulting

A person on devices, an E5 security uplift, or monthly care if you want one. Priced separately. Not required to run the package.

Package price depends on how many tenants you are standing up. A short note produces a real number, not a range published here.

Ready for the package?

Company IT or MSP. One tenant or many. Same conversation.
